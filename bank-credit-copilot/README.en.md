# Credit Copilot — loan underwriting assistant (demo)

[Tiếng Việt (main README)](./README.md)

A FastAPI demo of GenAI support for **credit officers** at a Vietnamese bank: it reads an unsecured consumer-loan file (ID card, loan application, labour contract, salary statement), checks 10 policy conditions, drafts a credit memo, and answers policy questions with clause citations. Every conclusion links back to the source line in the documents and to the policy clause it enforces.

> **Honest scope:** all applicants, documents and the policy are **synthetic**. No bank, LOS or core-banking (T24) connection. The default mode runs **offline with no API key**. The Gemini/OpenAI paths are covered by tests with a mocked model only and **have not been run against a live API key**. Output is a recommendation; the credit decision stays with a human approver.

## Design

- **The LLM never decides or calculates.** Income, instalment (annuity at the reference rate), DTI and pass/fail are computed in `app/rules.py`.
- **Number check:** any number in an LLM-written memo must appear in the computed facts or cited clauses, otherwise the template memo is used.
- **Quote check:** when the model is allowed to read documents, each extracted field must quote a line that exists in the file; the value is re-parsed from that line by code.
- **Data stays in the bank by default:** document text is not sent to a model unless `LLM_SEND_DOCUMENTS=true`; the memo prompt receives masked facts only. `LLM_PROVIDER=openai` works with any OpenAI-compatible on-prem server (vLLM, Ollama).
- **Audit:** every assessment and policy question is written to JSONL with masked ID numbers.

## Run

```bash
cd bank-credit-copilot
pip install -r requirements.txt
uvicorn app.main:app --reload     # http://127.0.0.1:8000
pip install -r requirements-dev.txt && python -m pytest -q && python scripts/evaluate.py
```

## Offline evaluation

4 synthetic cases and 16 policy questions: field extraction 100%, rule outcomes 100%, verdicts 100%, policy retrieval or correct refusal 93.8% (15/16; "Mở thẻ tín dụng cần gì" wrongly retrieves clause 6.4, a known lexical-search limitation). The cases are generated by this project, so these numbers show the logic works, not accuracy on real scanned documents.
